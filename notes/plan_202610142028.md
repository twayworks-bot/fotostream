## 1. 최소 기능 제품 (MVP: Minimum Viable Product) 정의

FOTOSTREAM 프로젝트의 핵심 가치를 가장 빠르고 안정적으로 입증할 수 있는 MVP 범위를 다음과 같이 정의합니다.

### 1.1 MVP 포함 핵심 범위 (Core Scope)
1. **환경 및 기본 설정**:
   - `.env` 연동 및 경로/포트(`5000`)/프리픽스(`/fotostream`) 로드
   - `FFMPEG_PATH`, `FFPROBE_PATH` 유효성 검사 및 안내
2. **NxM 그리드 계산 및 비디오 합성 엔진**:
   - $1 \le K \le 49$개 사진에 대한 $M=N$ 또는 $N = M \pm 1$ 최적 그리드 산출
   - 720p 해상도 기반 매트릭스 전체 뷰 $\rightarrow$ 개별 사진 줌인 $\rightarrow$ 줌아웃 복귀 $\rightarrow$ 순차 슬라이딩 렌더링
   - 선택된 BGM 오디오와 비디오 결합 (영상 길이에 맞춘 자동 루프 및 페이드아웃)
   - 최대 비디오 파일 크기 $\le 100\text{MB}$, 최대 재생 시간 $\le 10\text{분}$ 검증
3. **비동기 큐 및 동시성 제어**:
   - 동시 비디오 합성 작업 수 **최대 3개** 제한 (`asyncio.Semaphore(3)`)
   - 작업 상태 라이프사이클 관리 (`QUEUED`, `PROCESSING`, `COMPLETED`, `FAILED`)
4. **스트리밍 엔드포인트 및 동시 세션 제어**:
   - 최종 동영상 전용 스트리밍 URL (`/fotostream/api/v1/videos/{video_id}/stream`)
   - HTTP Range Request (206 Partial Content) 지원
   - 동시 스트리밍 세션 수 **최대 10개** 제한 (`ActiveStreamRegistry`)
5. **웹 대시보드 (Demo Admin UI)**:
   - `/fotostream` 경로를 통한 접근
   - 사진 다중 업로드(최대 49장) 및 BGM 선택 UI
   - 실시간 작업 큐 상태 모니터링 (대기 및 진행률)
   - 생성된 비디오 라이브러리 목록 확인 및 웹 플레이어 즉시 스트리밍 재생

## 2. 단계별 세부 개발 추진 계획 (Milestones & Work Breakdown)

### Phase 1: 기반 인프라 및 프로젝트 스캐폴딩 (Step 1)
- **목표**: 실행 환경 검증 및 기본 아키텍처 토대 구축
- **세부 작업**:
  1. Python 가상환경 의존성 명세(`requirements.txt`): `fastapi`, `uvicorn`, `pydantic-settings`, `pillow`, `sqlalchemy`, `aiofiles`, `jinja2`, `python-multipart` 등 정의
  2. `core/config.py`: `.env` 파일 매핑 및 `FFMPEG_PATH`, `FFPROBE_PATH` 검증 로직 구현
  3. `core/database.py` 및 SQLite 초기화 (`models/job.py`, `models/video.py`)
  4. 저장소 디렉토리(`storage/uploads`, `storage/transcoded`, `storage/hls`) 자동 생성기 구현

### Phase 2: 핵심 알고리즘 및 비디오 합성 엔진 개발 (Step 2)
- **목표**: 수학적 그리드 산출 및 줌인-아웃 비디오 인코딩 파이프라인 완성
- **세부 작업**:
  1. `services/grid_calculator.py`:
     - $K \in [1, 49]$에 대한 $N \times M$ 최적 그리드 산출 함수 구현
     - 각 셀별 픽셀 좌표 $(X, Y, W, H)$ 매핑 단위 테스트 작성
  2. `services/video_synthesizer.py`:
     - 베이스 720p 캔버스 생성 및 이미지 전처리(리사이징/레터박스)
     - Ease-in-out 코사인 줌인-줌아웃 트랜지션 프레임 제너레이터 구현
     - FFmpeg rawvideo 파이프라인 연동 및 MP4 인코딩
  3. `services/audio_mixer.py`:
     - BGM 오디오 길이 측정, 루프 믹싱, 페이드아웃 필터그래프 적용

### Phase 3: 작업 큐 및 동시성 제어기 구현 (Step 3)
- **목표**: 최대 3개 동시 합성 보장 및 비동기 워커 풀 가동
- **세부 작업**:
  1. `services/task_queue.py`:
     - `asyncio.Queue` 기반 비동기 대기열 구현
     - `asyncio.Semaphore(3)` 기반 동시 실행 슬롯 제한
     - 작업 상태 추적 및 DB 진행률 실시간 업데이트
  2. 취소(Cancel) 및 실패 예외 처리(에러 로그 기록) 로직 개발

### Phase 4: 스트리밍 매니저 및 비디오 API 구현 (Step 4)
- **목표**: 206 Partial Content 스트리밍 및 동시 10개 세션 제어
- **세부 작업**:
  1. `services/stream_manager.py`:
     - 활성 스트리밍 카운터 및 슬롯 잠금/해제 매니저 구현
     - 10개 초과 시 HTTP 429 반환 핸들러
  2. `routers/videos.py`:
     - HTTP `Range` 헤더 파싱 및 청크 스트리밍 응답(`StreamingResponse`) 구현
     - 비디오 목록, 상세 조회, 다운로드, 삭제 엔드포인트 구현

### Phase 5: RESTful API 및 시스템 모니터링 라우터 구축 (Step 5)
- **목표**: 프론트엔드 및 외부 클라이언트용 완전한 API 완성
- **세부 작업**:
  1. `routers/jobs.py`:
     - `POST /fotostream/api/v1/jobs` (멀티파트 사진 최대 49장 및 BGM 수신)
     - `GET /fotostream/api/v1/jobs/{job_id}` (상태 폴링)
     - `GET /fotostream/api/v1/jobs` (전체 큐 목록)
  2. `routers/system.py`:
     - `GET /fotostream/api/v1/system/status` (워커 슬롯, 스트림 슬롯, 디스크 현황)

### Phase 6: 웹 대시보드(Demo Admin UI) 개발 (Step 6)
- **목표**: 직관적이고 반응성이 뛰어난 단일 대시보드 UI 제공
- **세부 작업**:
  1. `templates/dashboard.html`:
     - 모던하고 깔끔한 UI 레이아웃 (헤더 통계 카드, 업로드 카드, 큐 카드, 비디오 라이브러리)
  2. `static/js/app.js`:
     - 이미지 드래그 앤 드롭 및 49장 초과 방지 프론트 검증
     - 실시간 작업 큐 상태 폴링(2초 주기) 및 프로그레스 바 애니메이션
     - 비디오 카드 목록 렌더링
  3. `static/js/player.js`:
     - 전용 스트리밍 URL 연동 모달 비디오 플레이어

### Phase 7: 통합 테스트 및 품질 검증 (Step 7)
- **목표**: 모든 기능 요구사항 및 제약사항 완벽 검증
- **세부 작업**:
  1. 이미지 1장, 9장, 49장 합성 시나리오 테스트
  2. 동시 인코딩 5개 요청 시 3개 동시 수행 + 2개 대기 검증
  3. 스트리밍 10개 동시 요청 시 11번째 요청 429 제한 검증
  4. 파일 크기($\le 100\text{MB}$) 및 재생시간($\le 10\text{분}$) 한계값 검증
  5. API 문서(Swagger/OpenAPI `/fotostream/docs`) 확인

## 3. 리스크 분석 및 대응 방안

| 리스크 요인 | 영향도 | 발생 가능성 | 대응 전략 |
| :--- | :--- | :--- | :--- |
| **FFmpeg 미설치/경로 오류** | 높음 | 보통 | 서버 기동 시 `bin/ffmpeg.exe` 확인 후, 미존재 시 상세 가이드 출력 및 Mock/Warning 모드 지원 |
| **대용량 원본 업로드 시 OOM** | 높음 | 보통 | 업로드 즉시 Pillow로 720p 규격으로 1차 다운스케일링 후 저장 |
| **비정상 연결 종료 시 스트림 슬롯 누수** | 높음 | 낮음 | `try...finally` 및 제너레이터 소멸자에서 확실한 슬롯 반환 보장, 30초 무응답 시 자동 타임아웃 세션 클린업 |
| **비디오 렌더링 지연** | 중간 | 보통 | 프레임 렌더링을 벡터 연산화하고 FFmpeg 빠른 프리셋(`preset fast`) 적용 |
