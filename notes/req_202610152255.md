## 2. 현재 스트리밍 지원방식 점검 및 분석 (Current Streaming Analysis)

### 2.1 기존 지원 방식
- **프로토콜**: 단일 MP4 파일 기반 HTTP Range Requests (HTTP 206 Partial Content).
- **엔드포인트**: `GET /fotostream/api/v1/videos/{video_id}/stream`
- **동시성 제어**: `ActiveStreamRegistry`를 통해 최대 동시 스트림 수 $M = 10$으로 제한.
- **클라이언트 재생 방식**: HTML5 `<video src="/api/v1/videos/{id}/stream">`을 통한 점진적 다운로드(Progressive Download).

### 2.2 한계점 및 개선 필요성
1. **버퍼링 지연 및 반응성**: 단일 MP4 파일 방식은 대용량 영상의 경우 헤더(moov atom) 파싱 및 특정 시점 탐색(Seek) 시 추가적인 Range 헤더 왕복이 발생하여 모바일 및 불안정한 네트워크에서 재생 지연이 발생함.
2. **동시성 슬롯 점유**: Range 요청 단위로 스트리밍 슬롯을 획득/반환하므로 대기 시간이 길어질 수 있음.
3. **표준 적응형 스트리밍 부재**: 웹/모바일 산업 표준인 HLS(HTTP Live Streaming) 미지원으로 세그먼트 단위 캐싱 및 신속한 청크 전송 이점을 온전히 활용하지 못함.

## 3. 요구사항 분석 및 HLS 아키텍처 설계 (Requirement Analysis & Design)

1. **HLS(HTTP Live Streaming, RFC 8216) 전면 지원**:
   - M3U8 플레이리스트(`playlist.m3u8`) 및 MPEG-TS 세그먼트 청크(`segment_%03d.ts`) 생성 및 제공.
   - 세그먼트 재생 시간(Segment Duration)을 **2초(`-hls_time 2`)**로 설정하여 Time-to-First-Frame(TTFF)을 최소화하고 플레이어 반응 속도를 극대화.
   - 키프레임 독립 세그먼트 플래그(`-hls_flags independent_segments`) 적용.

2. **비디오 합성 직후 실시간 HLS 자동 즉시 변환 (Instant Post-Synthesis Remuxing)**:
   - 비디오 합성(`synthesize_video`) 완료 즉시 백그라운드 워커에서 FFmpeg 스트림 복사 remuxing(`-c copy -bsf:v h264_mp4toannexb`)을 실행.
   - 영상 재인코딩이 아닌 패킷 복사 방식이므로 CPU 부하가 거의 없이 0.1~0.3초 내에 HLS 변환 완료.
   - `storage/hls/{video_id}/` 디렉토리에 플레이리스트와 세그먼트 파일 즉각 생성.
   - 미변환된 기존 영상이 요청될 경우를 대비하여 On-Demand Lazy 변환 폴백 메커니즘도 함께 탑재.

3. **RESTful HLS 스트리밍 엔드포인트 제공**:
   - `GET /fotostream/api/v1/videos/{video_id}/hls/playlist.m3u8`: HLS 플레이리스트 반환 (`application/vnd.apple.mpegurl`, no-cache, CORS 지원).
   - `GET /fotostream/api/v1/videos/{video_id}/hls/{segment_name}`: 개별 TS 청크 반환 (`video/MP2T`, public cache, CORS 지원).
   - `GET /fotostream/api/v1/videos/{video_id}/hls`: 마스터 플레이리스트로 자동 연결/반환.
   - 기존의 MP4 Range 요청 엔드포인트(`.../stream`)도 하위 호환성 및 파일 다운로드용으로 병행 유지.

4. **웹 대시보드 HLS 실시간 플레이어 연동 (hls.js & Native HLS)**:
   - 프론트엔드에 `hls.js` 라이브러리를 탑재하여 Chrome/Firefox/Edge/Android 등 모든 브라우저에서 HLS 스트리밍 지원.
   - Safari 및 iOS 브라우저에서는 네이티브 HLS(`application/vnd.apple.mpegurl`)로 자동 재생.
   - 만약 HLS 재생이 불가한 환경일 경우 기존 MP4 Range 스트리밍으로 자동 폴백.
   - 비디오 상세 팝업에 "⚡ HLS 실시간 스트리밍 활성화" 뱃지 표시 및 HLS 플레이리스트 URL 복사 기능 제공.

5. **자원 정리 라이프사이클**:
   - 비디오 삭제(`DELETE /videos/{video_id}`) 시 해당 비디오의 HLS 세그먼트 디렉토리(`storage/hls/{video_id}`)도 영구 삭제.

- **Step 2: 데이터베이스 모델 및 스키마 확장 (`app/models/video.py`, `app/schemas/video.py`, `app/core/database.py`)**

  - `init_db()`에 SQLite 경량 마이그레이션(`ALTER TABLE videos ADD COLUMN...`) 로직 추가.
  - `VideoResponse`에 `hls_url` 필드 추가.
- **Step 3: HLS 스트림 생성 및 관리 서비스 구현 (`app/services/hls_manager.py`)**

  - `ensure_video_hls(video, db)`: On-demand 검증 및 자동 생성.
  - `delete_video_hls(video_id)`: 디렉토리 재귀 삭제.
- **Step 4: 작업 큐 즉시 HLS 변환 연동 (`app/services/task_queue.py`)**
  - 합성 완료 시 즉시 `generate_hls_stream()` 호출 및 `Video.hls_url`, `Video.hls_path` 저장.
- **Step 5: 비디오 라우터 HLS 엔드포인트 구현 (`app/routers/videos.py`)**
  - `/videos/{video_id}/hls/playlist.m3u8` 및 `/videos/{video_id}/hls/{segment_name}` 라우트 등록.
  - 비디오 삭제 시 HLS 폴더 정리 연동.
- **Step 6: 웹 대시보드 및 JS 플레이어 HLS 연동 (`dashboard.html`, `app.js`)**
  - `hls.js` 스크립트 로드 및 `openVideoModal()` 내 HLS 스트리밍 바인딩.
- **Step 7: 단위/통합 테스트 작성 및 검증**
  - HLS 스트림 생성 및 플레이리스트/세그먼트 응답 엔드포인트 검증 테스트 작성 및 실행.
